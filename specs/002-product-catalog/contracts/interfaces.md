# Interface Contracts: Product Data, Imports, and Catalog

**Feature ID**: F002

**Status**: Planning baseline for team review; endpoints and schemas are not implemented.

## Catalog and import contract

Product IDs exposed to the app are StoreProduct identifiers, not source seller identifiers.
Foreign/missing product IDs return indistinguishable 404 results after authentication.
Users may not select an unrelated store_id. Admin routes require the Admin guard.

The upload format is the clean-products CSV from the existing offline Python
preparation CLI. Required headers and values must match the shared CSV contract;
raw/nonconforming files are rejected with structured errors. The Next.js import
service validates/stages rows, without reimplementing Python cleaning in routes.

| Interface | Request | Result / constraints |
| --- | --- | --- |
| POST /api/v1/admin/imports | CSV plus explicit source/snapshot metadata | Import ID, staged/validated/published/rejected state, row errors |
| GET /api/v1/admin/imports/{importId} | Admin | Row/error counts, checksum, source and publication evidence |
| POST /api/v1/admin/imports/{importId}/publish | Validated batch and explicit product/store mappings | Atomic snapshot publication; duplicate checksum returns existing batch |
| GET /api/v1/products | Search, category/status filters, page, page_size | Only current store entries; stable ordering and total |
| GET /api/v1/products/{productId} | Owned product ID | Clean-product DTO, store mapping, snapshot/source metadata |

page >=1; page_size 1..100 (default 20); search <=200 characters.
Source product ID and product name are nonblank; price is finite, nonnegative;
quantity_sold is a nonnegative integer when present. Missing essential cleaning
fields are rejected/audited rather than invented. Zero-price rows may be retained
with valid_for_model=false according to the existing pipeline, not silently enabled.
ratings 0..5 or null; discount_rate 0..1 or null; review/image counts nonnegative.
Preserve the required fields in docs/rules/data-contracts.md.
Row errors identify row number, field and reason; no raw customer secrets are logged.
No imports or fixtures are generated by this planning request.

## Shared guard and disclosure rules

All application mutations revalidate active session, role and persisted ownership on the server. Read DTOs contain only approved fields. Credentials remain server-side. Human/generated evidence is identified honestly. Reference sales are snapshot-based decision support, not a forecast.
